# CHAMELEON BG — производительность, 16 октября 2026

Оптимизирован существующий проект. Браузер для профилирования не подключён: приведённые ниже времена получены через Node Performance API, размеры — из файлов production-сборки. Это не замеры FPS, RAM, INP или загрузки страницы на устройстве.

## Обнаруженные расходы

1. Главный модуль статически импортировал базы голосовых ситуаций и аудирования. Начальный статический граф содержал 1.557 МБ JS.
2. Railway Academy при подсчёте и смене режима повторно строила все банки. Для каждого термина создавался и перемешивался большой список отвлекающих ответов: лишняя квадратичная работа. Первый замер трёх банков занимал 130.88 мс, медиана повторных запусков — 92.92 мс.
3. Aurora запускала подготовку полного аудиокаталога на главной: 5,489,956 байт JSON с 95,048 ссылками. Серверная озвучка повторно запрашивалась после воспроизведения для сохранения в кэш.
4. Service Worker предзагружал динамические JS-модули с учебными базами. Предельный автоматический аудиокэш составлял 100 000 записей; пакеты корпуса дублировались в Cache Storage и IndexedDB.
5. Поиск глаголов заново объединял и приводил к нижнему регистру весь каталог при рендерах. Статистика создавала Intl.DateTimeFormat на каждое обращение к дате. Полная история FSRS удерживалась и в корневом React-состоянии, хотя этому экрану нужны только текущие карточки.
6. Для карточек использовались JPEG общего размера. Были таймеры предполагаемой длительности звука без очистки и отсутствовала очистка распознавания речи при закрытии VoiceLab.

## Что изменено

- Голосовой раздел, аудирование, грамматический справочник, профессиональные уроки и данные разделов загружаются динамически. Для Railway подготовлен точный поднабор из 33 прежних диалогов вместо загрузки всех 409. Все исходные диалоги сохранены.
- Банки заданий кэшируются; варианты ответа перемешиваются только для выбранных заданий. Построение банков и подбор занятия выполняются в отдельном Worker. Worker завершается при закрытии раздела или после 45 секунд простоя; при его недоступности действует резервный путь. Сохранились история ошибок, неповторяемость и случайный выбор.
- Проверка контрольных сумм, разбор пакетов и построение поисковых токенов перенесены в Worker с передачей ArrayBuffer. Он создаётся только при необходимости установки и освобождается по завершении. Резервная индексация выполняется порциями.
- Добавлены индексы срока повторения. Алгоритм FSRS и полная история в IndexedDB сохранены; корневое состояние получает облегчённые копии карточек без копирования истории в React. Миграция прежней базы покрыта тестом.
- Каталог глаголов имеет предварительно подготовленные поисковые строки и мемоизацию. Результаты в прокручиваемом блоке виртуализированы, включая навигацию клавиатурой. Карточки и термины остаются ограничены страницами и используют content-visibility. JSON-запросы объединяются, постоянный кэш разобранных ресурсов ограничен.
- 594 фотографии получили 1188 WebP-вариантов. Picture/srcset учитывают реальную ширину файла; JPEG, исходные загрузки и лицензии сохранены. Используются lazy loading, асинхронное декодирование и предварительная загрузка только следующей карточки.
- Аудиокаталог разделён на 256 частей, самая крупная — 25,898 байт. Постоянный кэш разобранных частей ограничен восемью. На главной аудиоиндекс не запрашивается. Серверный звук воспроизводится и сохраняется из одного ответа; временные Blob URL освобождаются.
- Явно выбранное офлайн-аудио и его ссылки сохраняются отдельно от автоматического кэша. Лимиты нового автоматического кэша: 256 MP3, 32 части аудиоиндекса, 160 изображений, 240 грамматических пакетов и 100 модулей кода. Для кода и грамматики нет возрастного истечения, которое ломало бы долгий офлайн-перерыв. Прежние кэши медиа сохранены, поскольку могут содержать выбранные пользователем уроки.
- Service Worker предзагружает только оболочку и её статические зависимости: 22 ресурса, 1.261 МБ. Посещённые модули кэшируются по мере использования. Новые пакеты корпуса после установки хранятся в IndexedDB, без второй постоянной копии JSON в Cache Storage. Обновление приложения сохраняет прежний порядок подтверждения и не сбрасывает занятия.
- Aurora, неон, параллакс, Liquid Glass, 3D-переворот и клавиатура остаются. Наклон вынесен на внешнюю область карточки, отдельно от переворота. Геометрия не перечитывается на каждом движении указателя; снятые с экрана элементы и GSAP-ресурсы очищаются. Невидимые и фоновые анимации приостанавливаются. На слабых устройствах сохраняются два медленных световых слоя. Раскрытие фото использует transform/opacity, без покадрового blur. Визуализатор работает только во время реального воспроизведения и при доступном сигнале.

При проверке реального корпуса также исправлена ошибка BG → RU: 568 примеров имеют встроенный перевод при пустом массиве translations. Теперь используется существующий перевод и корректная атрибуция. Две короткие фразы без слов нужной длины не попадают в multi, но остаются в базе и других режимах. Новых учебных примеров для обхода тестов не добавлялось.

## Измеренные результаты

| Проверка | До | После |
|---|---:|---:|
| Начальный статический JS, без сжатия | 1.557 МБ | 0.662 МБ |
| Сумма gzip начального JS | 264,891 байт | 219,210 байт |
| Первое построение трёх банков после загрузки модулей, Node | 130.88 мс | 45.65 мс |
| Повторное обращение к трём банкам, медиана Node | 92.921 мс | 0.008 мс |
| Подбор 15 заданий без истории, медиана Node | 2.440 мс | 1.585 мс |
| Пакет из шести поисков глаголов, медиана Node | 5.857 мс | 0.682 мс |
| Суммарный размер JPEG / WebP до 320 px | 31.263 МБ | 7.952 МБ |

Начальный статический JS уменьшен на 57.5%, набор изображений до 320 px — на 74.6%. Gzip рассчитан локально и не является замером реальной передачи сервером. Время построения банков не включает запуск Worker, сеть и отрисовку. Повторный замер после изменения показывает обращение к кэшу, а не повторное создание всех заданий. Поиск измеряется по шести запросам вместе; построение индекса выполняется один раз.

Суммарный JS всех разделов вырос с 3.650 МБ до 4.112 МБ: добавились Worker и отдельный профессиональный поднабор. Этот код загружается при обращении к разделу, а не целиком на главной. Большие динамические блоки грамматики и диалогов остаются; предупреждение сборки о них не скрывалось.

## Проверка

- 62 теста в 17 файлах проходят: сохранение/восстановление занятий, FSRS, миграция истории, Worker-контракты, офлайн-аудио, освобождение Blob URL, отсутствие повторов, виртуализация и клавиатура.
- 145 заданий на реальном корпусе проверены во всех 25 механиках; проверена доступность основных генераторов на шести уровнях.
- TypeScript и production-сборка PWA проходят.
- По manifest и сгенерированному Service Worker подтверждено отсутствие учебных баз в начальном графе и массовой предзагрузки медиа.
- HTTP-проверка 2396 ресурсов: 87 пакетов корпуса, 215 грамматических JSON, 594 фотографии, 1188 WebP, 256 аудиочастей, JS-модули и 24 выборочных MP3. В сборке присутствуют все 49 825 ранее подготовленных MP3.
- Базы сохранены: 16 658 словарных статей, 58 587 словоформ, 17 819 предложений, 2701 доступный глагол, 2082 технических термина. Железнодорожные банки сохраняют 3949 / 2748 / 2072 задания.

## Непроверенные браузерные показатели

Нет фактических замеров первоначальной загрузки страницы, открытия Railway/грамматики, задержки нажатий, FPS, Long Tasks и RAM на реальном устройстве. Не выполнена визуальная проверка неона, параллакса и новых picture-обёрток; не прослушивался звук и не проверялся микрофон в браузере. Автоматические тесты и HTTP-проверка этого не заменяют. Фактический размер прежних пользовательских кэшей не исследовался.

В настройках доступен ограниченный по времени сбор кадров, Long Tasks и Event Timing, а также экспорт навигации, ресурсов, доступной heap-метрики и React-коммитов. Отсутствующий API не подменяется оценкой. Для React-коммитов нужен dev-режим или `npm run build:profile`; обычная production-сборка не включает профилирующий renderer.

Артефакты: `data/performance-before.json`, `data/performance-after.json`, `data/performance-build-check.json`, `data/responsive-photo-report.json`, `data/audio-lookup-report.json`, `data/production-check-report.json`. Повтор: `npm run performance:bench -- after`, `npx tsx scripts/check-performance-build.ts`, `python scripts/check-production.py` при работающем preview на порту 4173.
